# 2026-11-02 本子猎手（三站搜索 + 自动下载）初版

## 需求
用户要把之前「复制本子名 → 在 wn10 找 → 手动下」的流程做成软件：
- 粘贴完整文件名（常常是日文标题混中文标题 + 「第几步」「中文汉化」这类垃圾后缀）
- 在**紳士漫畫 / 禁漫天堂 / nhentai** 三站找同名作品
- 优先级：汉化 > 字幕组 > 个人 > 日文原版，**只下一个**
- 全名匹配不到就用关键字匹配，只要含日文标题能撞上就下
- 可手动选保存目录
- 站点地址要**从发布页实时解析**（老域名会失效）：紳士 `https://wnacg01.link/`、禁漫 `https://jmcomictt.site/`
- UI 要**液态玻璃 + 明暗双主题**，参考三个开源项目：
  - `LilycleHeart/qqnt-liuli-theme`（QQNT 琉璃主题：壁纸取色 + 磨砂玻璃）
  - `Leonxlnx/taste-skill`（排版纪律：不堆卡片、不用小号大写标签、两三级字号、留白优先）
  - `pbakaus/impeccable`（先色相再色阶、hairline 优先于阴影、不靠阴影堆层次）

## 站点接口（实测，做软件的核心依据）

### 紳士漫畫（wnacg）
- 发布页 `https://wnacg01.link/` 直连 200，页面里 `<a href="https://www.wnacg.buzz/">` / `www.wnacg.site` 是最新地址
- 搜索：`{base}/search/?q=<urlenc>&f=_all&s=create_time_DESC&syn=yes`，HTML 里 `href="/photos-index-aid-<aid>.html" title="<标题>"`，单页 48 条
- 下载页：`/download-index-aid-<aid>.html` → `FILE_NAME: "..."` + `href="//dl1.wn01.download/down/xxxx/md5.zip"`
- **路由**：`www.wnacg.*` 直连 000，必须走代理 7890；`dl1.wn01.download` 反而必须直连（走代理 502）
- **整文件 GET 会被挂死**（200 + Content-Length 但 0 字节），必须 Range 分片 8MB，2 路并发（4 路会回 194 字节垃圾）

### 禁漫天堂（JM）
- 发布页 `https://jmcomictt.site/` 里 `<span>` 列出候选域名：`18comic.vip`、`18comic.ink`、`comic18j-moco.work`、`comic18j-nico.site`、`comic18j-ada.work`、`jmcomic-zzz.one`
- **实测 `comic18j-nico.site` 直连可用**（18comic.vip 直连 000 / 代理 403）
- 搜索：`{base}/search/photos?search_query=<urlenc>&page=1&main_tag=0` → `div.thumb-overlay > a[href="/album/<id>/<slug>"]` + `img[title]`（注意 href 带 slug，正则只能取 `/album/(\d+)`）
- 相册页：`/album/<aid>/` → 「开始阅读」链接 `/photo/<aid>`（多章节时是 `/chapter/<cid>`）
- 阅读页：`/photo/<aid>` 里有 `var aid`、`var scramble_id`、`var page_arr = ["00001.webp",...]`，CDN 主机从 `data-original="https://cdn-mspN.<host>/media/photos/..."` 取
- 图片 `{cdn}/media/photos/{aid}/{filename}` **实测是合法 WebP，没有加密/打乱**（scramble_id=220980 也不影响）

### nhentai
- 必须走代理（直连 000）
- v2 API：`/api/v2/search?query=<urlenc>` → `{"result":[{id,media_id,english_title,japanese_title,num_pages,tags?}]}`（v1 `/api/gallery/<id>` 已 403）
- 详情：`/api/v2/galleries/<id>` → `title{english,japanese}`、`tags[{type,name}]`（language: chinese/translated）、`pages[{number,path}]`
- CDN：`/api/v2/cdn` → `i1..i4.nhentai.net`；图片 `{server}/{path}`（path 形如 `galleries/<media_id>/1.webp`）
- **图片直连 000，必须走代理，速度慢（约 25 KB/s）** → 必须并发抓

## 实现

### 工程
`E:\本子猎手\`：`src\AppHost.cs`（WinForms 宿主 + WebView2 + 壁纸截图 + 消息桥 + 任务调度）、`src\Core.cs`（HTTP 双路由、配置、域名解析、标题归一化/相似度/优先级）、`src\Sites.cs`（三站搜索+下载、并发抓图、zip 打包）、`ui\index.html`（界面，构建时嵌进 exe）、`build.ps1`（csc 4.8 编译）。

### UI 三次重做（这是本次最费时间的部分）
1. **第一版 WinForms 原生控件**：方块 UI，用户直接说丑。
2. **第二版 WebView2 + 玻璃卡片**：DWM 亚克力在本机不生效（`DwmSetWindowAttribute(38)` 返回非 0），窗口标题栏还是旧式 Win10 蓝色（csc 的 `/win32manifest` 没编进去，exe 里搜不到 `supportedOS`）。→ 放弃 DWM，改为**自己截桌面当底图**。
3. **第三版（当前）**：无边框自绘窗口（`WS_THICKFRAME` + `WM_NCCALCSIZE` 归零，保留缩放/投影；`WM_GETMINMAXINFO` 扣任务栏；`WM_NCHITTEST` 自绘拖动/边角）+ 单层玻璃（`backdrop-filter: blur(38px) saturate()` 作用在壁纸截图上，不再嵌套）+ 壁纸取色（C# 采样 40×24 平均色 + 最鲜艳色，推给页面算 OKLCH 风格强调色）。

### 踩过的坑（以后别重踩）
1. **`web.CoreWebView2` 不能跨线程访问** —— 后台搜索线程里调 `Send()` 直接抛 `InvalidOperationException: CoreWebView2 can only be accessed from the UI thread`，进程崩（有 `CrashSender.exe` 弹窗）。修法：init 时缓存 `core` 引用，`Send()` 里一律 `BeginInvoke` 回 UI 线程再 `PostWebMessageAsJson`。
2. **WinForms 控件尺寸 ≠ 页面 viewport**：自己算 `--vh` 反而把 #app 撑到 1300px（页面只有 824），底部的日志和状态栏被顶出窗口。修法：页面用 `height:100%` 自己的 viewport，不信宿主给的数。
3. **副屏是 1920×1080 @125%**：`MoveToSecondary.ps1` 报的是逻辑坐标 1536×864，实际物理 1920×1080。按逻辑坐标截图只截到左上角 1536×864，误判「布局被切掉」，绕了好几轮。**截图前先看 `GetSystemMetrics` / `DwmGetWindowAttribute`**。
4. **`new { base = ... }` 编译不过**：`base` 是 C# 关键字，匿名类型成员不能叫 base（`error CS0746`）。改 `baseColor`。
5. **JM 域名「首页能开」不等于「能搜」**：`18comic.ink` 首页 200 但 `/search/photos` 返回 0 字节 → 搜索全空。修法：`ResolveJm` 里对候选域名做一次真实搜索探测，能出 `/album/` 才算可用。
6. **PowerShell 5.1 写含中文的 .ps1 必须 UTF-8 with BOM** —— 否则 csc 的 `/out` 路径被按 ANSI 解码，生成 `鏈瓙鐚庢墜.exe` 这种乱码文件名。build.ps1 / build-test.ps1 都已加 BOM。
7. **nhentai 串行抓图 7 秒一张**（83 页要 10 分钟）→ 改 4 路并发后 30 多秒下完。

## v3.1 回退到液态玻璃（2026-11-02 傍晚，用户反馈）

用户原话：「这个前端UI实在是太丑了，就不行，你就改回原来那个液态玻璃吧。你现在这个做的，如果不套那个壳的话，丑得要死，受不了」

### 判定
v3.0 为了把内存从 452MB 压到 63MB，把 WebView2 换成 WinForms + GDI+ 全自绘。但 GDI+ 的「截屏 → 模糊 → 画上去」只能模拟玻璃，做不到真 backdrop-filter（见 v3.0 那条结论），卡片边框 / 圆角 / 文字抗锯齿全面退化 → 用户判定丑。
取舍明确：**颜值优先，接受 WebView2 的内存开销**。所以不是修补 v3.0，而是整套 UI 回退。

### 改动
1. `src\NativeApp.cs` → `src\NativeApp.cs.gdi.bak`（移出编译范围留档，不删；build.ps1 只收 `*.cs`，改名即生效）
2. `src\AppHost.cs` ← 从 `AppHost.cs.webviewbak` 原样恢复（WebView2 宿主 + 无边框自绘窗口 + 消息桥）
3. `build.ps1` 重写成 WebView2 版：加 `Microsoft.Web.WebView2.Core.dll` / `WinForms.dll` 引用，加 `/resource:ui\index.html,index.html` 把界面嵌进 exe，编译后自检 `manifest=` / `ui_embedded=`（在 exe 字节里搜 `backdrop-filter`）
4. `ui\index.html` 版本号 v2.3 → v3.1（顶栏 `.ver` 与设置面板 `#setVer` 两处）
5. **额外修一个体验坑**：`CaptureDesktop()` 原来直接 `CopyFromScreen` 截当前显示器 → 窗口一显示就把自己（以及桌面上别的窗口，比如 QQ）截进玻璃底图，越用越脏、深色主题下糊成一坨黑。改成**优先读注册表 `HKCU\Control Panel\Desktop\WallPaper` 指向的壁纸文件**，按目标尺寸 cover 居中裁切；读不到文件才回退截屏。

### 教训
1. **截屏当玻璃底图是错的**：桌面只要有别的窗口，就会被糊进玻璃里。要「透出壁纸」就直接读壁纸文件。
2. WebView2 可以用 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 挂 CDP 做 UI 自动化验证，比 UIA 点 WebView2 内容可靠得多（UIA 里只能看到窗口框架按钮）。
3. 用户要的不是「低内存」，是「好看」。v3.0 是方向性错误，记在此避免再犯。

1. **PowerShell 的 `Set-Clipboard` 写不了剪贴板**：剪贴板被其它进程占着时直接抛 `ExternalException`。要测剪贴板必须走 Win32：`OpenClipboard` 重试 25 次 + `GlobalAlloc(GMEM_MOVEABLE|GMEM_ZEROINIT = 0x0042)` + `GlobalLock` + `Marshal.Copy` + `SetClipboardData(CF_UNICODETEXT = 13)` + `CloseClipboard`。

3. **`Enter` 里调 `blur()` 会造成二次提交**：keydown 的 commitDir 先发，宿主还没回 `dir`，此时 `#path` 还是旧值 → blur 比较「值≠path」→ 又提交一次，日志重复两条。改成 Enter 不 blur（只 `select()`），避免依赖 blur。
4. **不校验绝对路径就会造垃圾目录**：`Directory.CreateDirectory("hello world")` 会在程序工作目录（`E:\本子猎手\`）里真建出文件夹。必须先用盘符/UNC 形状校验挡掉。
5. WebView2 里粘贴不能靠系统快捷键：`AppHost` 设了 `AreBrowserAcceleratorKeysEnabled=false`，Ctrl+V 系统层不可靠，所以 Ctrl+V 走 JS 拦截 → 宿主读剪贴板 → 回传填充，这条链路是可控的。

## v3.3 界面闪烁排查 + 全链路文件日志（2026-11-02 傍晚）

用户原话：「我现在打开了实际的 exe 应用，它会隔几秒闪烁一下，不知道是什么 bug 需要修复。另外，你的日志一定要做详细啊。我记得这个是在你记忆里写死的。日志越详细，你才能在运行过程中检查到问题」

### 先说结论
闪烁没有单一「某行代码写错」，是三个东西叠在一起，全部落在「每次窗口移动 → 重抓壁纸」这条路上：

1. **主线程同步抓壁纸**：窗口任何一次 Move/Resize，700ms 后 `bgTimer` 触发 `CaptureDesktop()`，在 UI 线程里把 3840×2160 壁纸 bicubic 缩到屏幕尺寸再存 PNG，**实测单次 665–873ms**。这段时间窗口完全冻结，用户看到的就是「卡一下 / 闪一下」。
2. **抓图撞文件锁**：构造时已经开始后台抓、`if (!File.Exists(bg.png)) CaptureDesktop()` 又抓一次，同时 WebView2 正在读 `bg.png` 当玻璃底图 → `bmp.Save()` 抛 `ExternalException: GDI+ 中发生一般性错误`，bg.png 有可能是半写状态 → 玻璃底图失效 → 界面重载时露黑/闪。
3. **`DefaultBackgroundColor` 固定 `Color.Black`**：浅色主题下任何一次重绘都会先露黑底。
4. 附带：`setBg()` 用 `Date.Now.Ticks` 做 URL 参数，**每收到一次 bg 消息就换一个 URL 重新解码**，即使图片根本没变。

### 排查过程（三次抓帧都失败，最后靠日志定位）
- **屏幕 CopyFromScreen 抓窗口区域**：抓到的是 B 站视频 —— 窗口被遮挡，抓到的是上层窗口，差异 85%，全是假的。
- **PrintWindow(PW_RENDERFULLCONTENT=2)**：抓到真实界面，8 帧字节完全相同 → 客户区静止。
- **CDP `Page.captureScreenshot`**：40 帧（20 秒）字节完全一致。
- **CDP `Page.startScreencast`**：Chromium 只在画面变化时才推帧，25 秒只推了 1 帧 → **页面渲染层 25 秒零变化**。
- **结论**：网页不动、客户区不动 → 问题在窗口/合成层，不在 HTML。于是上日志，一把抓到 GDI+ 报错和 800ms 的同步抓图。
